# 公共 API 接入清单

> 当前为待办清单，不是现有后端 API 文档。用户要求等后端完成后再联调；本次没有向后端发起业务请求，也没有修改后端代码。

## 当前接口事实

`../white-blog-admin/blog-manage-serve/routes/index.ts` 当前有 `GET /`、管理员注册/登录接口及 `GET /Comment`；未见公共文章、图库、日记、作品、个人资料或媒体清单接口。`GET /Comment` 未确认审核和公开范围，不直接接到前台。用户提供的接口文档截图展示文章/图库共用 `/createArticle` 写入结构，靠 `classify` 区分，但此路由尚未见于当前服务端代码。前台全部业务内容目前来自 `app/data/mock.ts`。

个人网站的阅读页面对所有人开放，不需要登录。后续公共只读接口也应可匿名访问；后台创建、编辑和管理操作继续使用后台身份验证。

## 后端准备后需确认

| 内容 | 前台需要 | 后端需给出的契约 |
| --- | --- | --- |
| 站点与公开资料 | White 字标、公开介绍、SEO 信息 | 可公开字段、缺失值、更新方式；与管理员账号隔离 |
| 文章列表 | 首页精选、文章页、归档 | 已发布过滤、稳定 URL 标识、日期、封面、摘要、分类标签、分页/筛选/搜索及排序 |
| 文章详情 | 标题、正文、目录、图片、前后篇 | 标识解析、404 语义、正文格式、媒体 URL、富文本净化和外链安全 |
| 相册列表 | 封面、标题、分类、标签、简介、日期、浏览量 | 从 `article.classify = 1` 且已发布的记录读取，提供分页、筛选和稳定公开 URL |
| 相册详情 | 图片集合、标题、简介、日期、分类标签、评论点赞汇总 | 确认 `article.content` 图片地址的序列化格式、媒体访问与缺失图片处理；与文章共用模型但按类型展示 |
| 作品 | 分类与图文展示 | 是否建立作品模型、公开字段、封面与可选详情链接 |
| 片刻记录 | 首页摘要与时间页的标题、正文、图片、天气、心情、日期 | `diary.picture` 的序列化格式、`weather_id` 关联、`mood` 数值对应含义、公开规则和分页方式 |
| 媒体 | 封面和正文图 | 可访问 URL、尺寸、替代文本、缓存与权限 |

评论、点赞、留言或访问统计没有纳入初版写入能力。若后续增加，先明确身份、频率限制、审核与隐私；统计只能使用允许公开的聚合数据。后台账号密码、私信和原始访问记录不属于个人网站的公开内容。

## 联调实施顺序

1. 与后端确认公共只读接口、字段、错误格式、部署地址、是否同源以及文章正文存储格式。当前 `slug` 仅是 Mock 标识，不能当成已存在的服务端字段。
2. 在 Nuxt `runtimeConfig` 中放服务端地址，增补 `.env.example`；定义**实际响应类型**及到页面视图模型的转换。SSR 请求应使用服务端可达地址，不在浏览器写死本机端口。
3. 逐页用真实 API 替换 Mock，处理加载、无内容、请求失败、404 和图片失败；公开读取不要求登录，也不能依赖管理员接口或仅靠前台过滤草稿。
4. 验证管理端发布/更新后前台可见、草稿不可见，检查 SSR 首屏、分页筛选、移动端、SEO、跨域与缓存。正式域名确定后补 canonical、sitemap、robots。

管理端当前的 wangEditor 富文本 HTML 与原需求中的 Markdown 目标不同。接入前必须选定一种实际格式，并在可信服务端或受控转换层净化任意 HTML；现有结构化演示章节不能直接当成真实文章接口字段。
